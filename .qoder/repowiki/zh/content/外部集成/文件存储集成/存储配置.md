## 存储配置结构体详解

`storager.Config` 结构体（在代码中实际为 `model.UploadConfig`）定义了系统中所有文件上传和存储相关的配置参数。该结构体包含了通用配置、本地存储配置以及多种云存储服务的配置。

### 通用配置
通用配置字段适用于所有存储驱动，定义了文件上传的基本限制和规则：
- **Drive**：存储驱动类型，指定系统使用的存储后端，如本地存储、腾讯云COS、阿里云OSS等。
- **FileSize**：文件大小限制，单位为字节，用于限制上传文件的最大尺寸。
- **FileType**：允许的文件类型，通过文件扩展名进行限制，确保只允许特定类型的文件上传。
- **ImageSize**：图片文件大小限制，专门针对图片文件的大小限制。
- **ImageType**：允许的图片类型，限制可上传的图片格式。

### 云存储配置
系统支持多种云存储服务，每种服务都有其特定的配置字段：

#### 腾讯云COS配置
- **CosSecretId**：COS服务的SecretId，用于身份验证。
- **CosSecretKey**：COS服务的SecretKey，用于身份验证。
- **CosBucketURL**：COS存储桶的访问URL。
- **CosPath**：在COS存储桶中的基础路径，用于组织文件。

#### 阿里云OSS配置
- **OssSecretId**：OSS服务的AccessKey ID。
- **OssSecretKey**：OSS服务的AccessKey Secret。
- **OssEndpoint**：OSS服务的接入点地址。
- **OssBucketURL**：OSS存储桶的访问URL。
- **OssPath**：在OSS存储桶中的基础路径。
- **OssBucket**：OSS存储桶名称。

#### 七牛云配置
- **QiNiuAccessKey**：七牛云的AccessKey。
- **QiNiuSecretKey**：七牛云的SecretKey。
- **QiNiuDomain**：七牛云存储的CDN域名。
- **QiNiuPath**：在七牛云存储中的基础路径。
- **QiNiuBucket**：七牛云存储桶名称。

#### MinIO配置
- **MinioAccessKey**：MinIO的访问密钥。
- **MinioSecretKey**：MinIO的密钥。
- **MinioEndpoint**：MinIO服务的端点地址。
- **MinioUseSSL**：是否使用SSL加密连接。
- **MinioPath**：在MinIO存储中的基础路径。
- **MinioBucket**：MinIO存储桶名称。
- **MinioDomain**：MinIO存储的CDN域名。

#### UCloud配置
- **UCloudBucketHost**：UCloud存储桶的主机地址。
- **UCloudBucketName**：UCloud存储桶名称。
- **UCloudEndpoint**：UCloud服务的接入点。
- **UCloudFileHost**：UCloud文件的访问主机。
- **UCloudPath**：在UCloud存储中的基础路径。
- **UCloudPrivateKey**：UCloud的私钥。
- **UCloudPublicKey**：UCloud的公钥。

### 本地存储配置
- **LocalPath**：本地文件系统的存储路径，指定上传文件在服务器上的保存位置。

## 多存储后端配置

系统支持通过 `config.yaml` 文件配置多个存储后端，允许根据不同的业务需求选择合适的存储方案。配置文件中的 `upload` 分组包含了所有存储相关的配置项。

```yaml
# 上传配置
upload:
  # 通用配置
  drive: "local"
  fileSize: 20971520
  fileType: "jpg,png,gif,jpeg,webp,bmp,mp4,avi,wmv,rmvb,mkv,mp3,wav,flac,ape,ogg"
  imageSize: 10485760
  imageType: "jpg,png,gif,jpeg,webp,bmp"
  # 本地存储配置
  localPath: "./storage/upload"
  # 腾讯云cos配置
  cosSecretId: "your-cos-secret-id"
  cosSecretKey: "your-cos-secret-key"
  cosBucketURL: "https://your-bucket.cos.ap-beijing.myqcloud.com"
  cosPath: "uploads/"
  # 阿里云oss配置
  ossSecretId: "your-oss-access-key-id"
  ossSecretKey: "your-oss-access-key-secret"
  ossEndpoint: "oss-cn-beijing.aliyuncs.com"
  ossBucketURL: "https://your-bucket.oss-cn-beijing.aliyuncs.com"
  ossPath: "uploads/"
  ossBucket: "your-bucket-name"
  # 七牛云对象存储配置
  qiNiuAccessKey: "your-qiniu-access-key"
  qiNiuSecretKey: "your-qiniu-secret-key"
  qiNiuDomain: "https://your-domain.qiniu.com"
  qiNiuPath: "uploads/"
  qiNiuBucket: "your-bucket-name"
  # minio配置
  minioAccessKey: "your-minio-access-key"
  minioSecretKey: "your-minio-secret-key"
  minioEndpoint: "localhost:9000"
  minioUseSSL: 0
  minioPath: "uploads/"
  minioBucket: "hotgo"
  minioDomain: "https://minio.example.com"
```

通过设置 `drive` 字段的值，可以轻松切换不同的存储后端。例如，设置为 `local` 使用本地存储，设置为 `cos` 使用腾讯云COS，设置为 `oss` 使用阿里云OSS等。

## 配置验证与默认值

系统在加载存储配置时会进行验证，并设置合理的默认值以确保系统的稳定运行。

### 配置验证
配置验证主要在 `GetUpload` 方法中完成，该方法从数据库中获取上传配置并进行类型转换：
- 检查配置分组是否为空。
- 从数据库 `sys_config` 表中查询指定分组的配置项。
- 使用 `gconv.Scan` 方法将查询结果转换为 `UploadConfig` 结构体。
- 对敏感信息进行过滤和脱敏处理。

### 默认值设置
系统为关键配置项设置了合理的默认值：
- **FileSize**：默认为20MB（20971520字节）。
- **ImageSize**：默认为10MB（10485760字节）。
- **LocalPath**：默认为 `./storage/upload` 目录。
- **Drive**：默认为 `local`，即使用本地存储。

这些默认值可以在 `config.yaml` 文件中进行覆盖，以满足不同环境的需求。

## 环境配置示例

根据不同环境（开发、测试、生产），可以提供相应的配置示例。

### 开发环境配置
开发环境通常使用本地存储以便于调试和开发：
```yaml
upload:
  drive: "local"
  fileSize: 52428800
  fileType: "jpg,png,gif,jpeg,webp,bmp,mp4,avi,wmv,rmvb,mkv,mp3,wav,flac,ape,ogg,doc,docx,xls,xlsx,pdf"
  imageSize: 20971520
  imageType: "jpg,png,gif,jpeg,webp,bmp"
  localPath: "./storage/upload"
```

### 生产环境配置
生产环境推荐使用云存储服务以获得更好的性能和可靠性：
```yaml
upload:
  drive: "oss"
  fileSize: 104857600
  fileType: "jpg,png,gif,jpeg,webp,bmp,mp4,avi,wmv,rmvb,mkv,mp3,wav,flac,ape,ogg"
  imageSize: 52428800
  imageType: "jpg,png,gif,jpeg,webp,bmp"
  ossSecretId: "${OSS_SECRET_ID}"
  ossSecretKey: "${OSS_SECRET_KEY}"
  ossEndpoint: "oss-cn-beijing.aliyuncs.com"
  ossBucketURL: "https://production-bucket.oss-cn-beijing.aliyuncs.com"
  ossPath: "uploads/"
  ossBucket: "production-bucket"
```

## 配置热加载机制

系统实现了配置热加载机制，允许在不重启服务的情况下更新存储配置。

### 热加载流程
1. 当通过管理后台更新配置时，`UpdateConfigByGroup` 方法被调用。
2. 更新数据库中的配置项。
3. 调用 `syncUpdate` 方法同步更新内存中的配置。
4. 根据配置分组触发相应的 `SetConfig` 方法更新服务配置。

### 关键代码
```go
func (s *sSysConfig) syncUpdate(ctx context.Context, in *sysin.UpdateConfigInp) (err error) {
	var cfg any
	switch in.Group {
	case "upload":
		cfg, err = s.GetUpload(ctx)
		if err == nil {
			storager.SetConfig(cfg.(*model.UploadConfig))
		}
	}
	return
}
```

### 集群同步
在集群部署模式下，配置更新会通过Redis发布订阅机制同步到所有节点：
- 使用 `global.PublishClusterSync` 发布配置更新事件。
- 各节点监听 `ClusterSyncSysconfig` 事件。
- 收到事件后调用 `LoadConfig` 重新加载所有配置。

这种机制确保了配置的一致性和实时性，提高了系统的可用性和维护性。
